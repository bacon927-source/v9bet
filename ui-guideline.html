V9Bet Mobile web UI guideline

Mobile web 的畫面怎麼做。這一版是現有產品（APP-V9Bet-v1）的升級：保留 V9Bet 讓人認得的樣子，可用性和一致性照這份規範。設計稿在 Figma V9Bet Mobile Web — UI，實作是 Tailwind CSS 的元件 class。元件一節的範例是真的元件 class；設定、引導與面板那一節放的是 Figma 的圖，可以操作的範例和寫法在 UI kit。

原則 · 基礎 · 頁面結構 · 頁面模式 · 元件 · 新元件（Figma） · 文案 · 加新元件 · 不要做的事

做好的頁面：Login · Sign Up 　工程師用的參考：UI kit

原則

  • 以 v1 為基礎的升級版。保留讓人認得的部分：黃色主按鈕、外框輸入框和浮起來的標籤、深色、系統字體。可用性和一致性的問題直接改，不用為了跟 v1 一樣而保留——改過哪些列在「基礎」最後。v1 沒有的東西照這份規範做，不必去 v1 找先例。
  • 內容和流程照 wireframe。這份規範決定長相，wireframe 決定有哪些欄位、順序和文案。
  • 頁面只組合元件。按鈕、輸入框、分頁這些都是定義好的 class（.btn、.field、.tab…），頁面用 utilities 排版，不在頁面裡重新刻一顆。
  • 值只有一個來源。顏色、字級寫在 variables.css；tailwind.config.js 把它們變成 theme 和元件。頁面裡不寫色碼。
  • 先看 360。越南和泰國最常見的手機寬度是 360，每一頁都要在這個寬度檢查過才算完成。

頁面結構

每一頁都是同一個骨架，順序是：先定左右邊距（.page，px-4 16），再放頂列，然後內容從上往下排。頂列和內容自己都不帶左右邊距。按鈕緊接在表單後面，最後是通往另一頁的連結列。

<body class="bg-app text-ink font-sans antialiased">
  <div class="min-h-[100dvh] flex justify-center bg-app">
    <div class="page w-full md:max-w-[440px] md:border-x md:border-edge-subtle min-h-[100dvh]">

      <div class="nav-top"> … </div>

      <div class="page-body">
        <!-- 區塊由上往下，彼此間距 16（gap-4，.page-body 已經帶了） -->
        <div class="flex flex-col gap-2"> 欄位 … </div>
        <button class="btn"> … </button>
        <p class="link-row"> … </p>
      </div>

    </div>
  </div>
</body>
  • 不預留上下的安全區。Mobile web 外面已經有瀏覽器的網址列和工具列。裝置自己回報的 inset 由 .safe-top 和 .page-body 處理，不要寫死數字。
  • 不放 logo。這些頁面嵌在網站裡，網站的 header 已經有 logo。
  • 寬度 600 以上時內容置中、最寬 440，其他寬度都是同一套版面，不另外做平板版。
  • 一頁的區塊順序：其他登入方式 → 分隔線 →（分頁）→ 欄位 → 勾選或輔助連結 → 主按鈕 → 連結列。

頁面模式

Figma 的畫面是 iPhone 390 × 844，上下套了 v1 的 Safari 外框（狀態列＋網址列、工具列），那只是讓畫面看起來像在手機的瀏覽器裡。網頁不畫這兩條，也不替它們留空間——瀏覽器自己有網址列和工具列，頁面只加裝置回報的 env(safe-area-inset-*)。

同一類的頁面用同一個骨架。先決定這一頁是哪一種，再放元件。

短頁：按鈕跟在表單後面

內容一屏放得下的頁面（Login、Sign Up、選幣別）。

  • 主按鈕緊接在最後一個欄位後面，不釘底。
  • 按鈕下面一行連結列，帶去相關的另一頁。

長頁：按鈕釘在底部

內容比畫面高、而且整頁只有一個動作的頁面（Account Setup 總覽）。

  • 按鈕放在底部的按鈕列裡，內容在它後面捲動。
  • 按鈕列是實心底色加上一條細線，捲動的內容會被乾淨切掉。
  • 可以跳過的頁面，按鈕下面多一行文字連結（Skip this step）。
  • 底部要再加上手機回報的安全區（env(safe-area-inset-bottom)）。

引導式：一頁一件事

新會員的 Setup，像剛拿到手機時的開機設定。內容照 wireframe，只是一項一頁。

  • 上方：左邊返回，中間是灰色小字的「2 of 8」。頂列不放標題，第幾步只在這裡出現一次。
  • 每一頁都有頂列，不能空著。頂列下面不放麵包屑：回上一層靠頂列左邊的 ✕ 或返回。
  • 開場頁（Set Up Your Account）還沒進到第幾項，用一般的頂列：左邊 ✕、標題「Account Setup」；按 ✕ 先離開，Step 1 沒做完就不能存款或下注。
  • 中間：18 的標題（跟其他頁的標題同一個字級）、一句為什麼（「+10 points」2026-10-21 拿掉）。不放編號圈，進度已經在頂列。下面才是要填的東西。
  • 下方：按鈕釘在底部。可以跳過的項目多一個「Set up later」；必填的沒有。
  • Step 2、Step 3 開始前各有一個岔路頁，列出這一段的項目，可以整段跳過。
  • 之後從 Settings 回來補做，打開的是同一張頁面，只是返回回到 Account Setup、不顯示進度、沒有「Set up later」。

結果頁

一件事做完之後告訴使用者發生了什麼（帳號建立、登入、綁定完成）。

  • 綠圈加勾、一行綠色小標說發生什麼、大字說你是誰、一句補充、一顆 Continue。
  • 沒有 ✕，只能往下走。
  • 壞消息（帳號受限）不放綠圈，只有文字和下一步。

面板（從底部上來）

要使用者先處理一件事、但不離開目前的頁面時（例如帳號已存在，直接輸入驗證碼登入）。

  • 底下的頁面蓋一層 60% 黑，面板是第二層底色，上方圓角 12。
  • 最上面：把手、置中的標題、右上的關閉。
  • 一個面板一件事、一顆主按鈕。

設定清單

Settings 這類由很多項目組成的頁面。

  • 相關的項目放在同一張卡片裡，卡片上面一行分組標題（15、灰）。
  • 點了會開新頁的項目：右邊寫現況（Not added、091***233、Dark）加箭頭。
  • 立刻生效的開關：右邊放開關，不要箭頭。
  • 還沒完成、有點數的項目，在現況後面加「+10」。

選項卡片

從兩到四個選項裡選一個，而且每個選項需要一行說明（幣別、主題、訊息管道、收驗證碼的方式）。

  • 整張卡片都可以點，不只是左邊的圈。

要加新元件的時候

  • 先去 v1 的設計稿找有沒有現成的。有就照它的數字做。
  • 把它加進 tailwind.config.js 的 addComponents，顏色和字級都讀 variables.css 裡的變數。
  • 在這一頁補上範例、規格和規則。
  • 然後才在頁面裡用。沒有寫進這一頁的樣式，不要出現在頁面上。

不要做的事

  • 按鈕變紅來表示出錯。
  • 用 #5C6570 當文字顏色。
  • 用紫色當開關、連結或選中狀態。
  • 引導頁一頁放兩件事，或每一頁都放一張大插畫。
  • 為了跟 v1 一樣而保留已知的可用性問題。
  • 在頁面裡用 utilities 重新刻一顆按鈕或輸入框。
  • 寫死色碼（bg-[#FFBC00]）或用 Tailwind 的 dark: 前綴——深淺色由變數決定。
  • 一頁放兩顆黃色按鈕。
  • 自己畫第三方的品牌圖示。
  • 在最上面或最下面預留一條空白當安全區。
  • 提出新的視覺方向。視覺照 v1。
