進站三條路

Three Ways In
註冊和登入是同一個畫面的兩個分頁，出口也是同一個。但三條路裡只有一條會建立帳號，也只有那一條會經過 Setup。
Sign up and Login are two tabs on one screen, and they share one destination. But of the three routes, only one creates an account — and only that one goes through Setup.

三條路各自的規則

What each route actually does
Route ①

註冊 · 全新 email

Sign up with a new email
唯一會建立帳號的路。Email 送出後寄 6 位數碼，通過就建立帳號並自動產生 Account ID，接著強制進 Setup。
The only route that creates an account. A 6-digit code is sent, and passing it creates the account with an auto-generated Account ID, then goes straight into Setup.

Route ②

註冊 · email 已存在

Sign up with an email that already has an account
同一個欄位、同一組驗證碼，只是結果不同：跳出置中 modal，碼在 modal 裡輸入，通過就登入。不會建立第二個帳號，也不重跑 Setup。
Same field, same code — only the outcome differs. A centred modal appears, the code is entered inside it, and passing it signs them in. No second account, and no repeat of Setup.

三條路共用的規則

Rules that hold across all three
驗證前不透露
Nothing before the code
帳號存不存在、是休眠還是被限制，在驗證碼通過之前一律看不出來。註冊頁是唯一的例外——那裡會明講 email 已註冊，是業務決定，所以必須靠限流補上。
Whether an account exists, and whether it is dormant or restricted, is invisible until the code passes. The sign-up screen is the deliberate exception — it says the address is taken, which is why rate limiting carries the weight there.
Setup 只做一次
Setup happens once
只有新建立的帳號會被推進 Setup。既有帳號回來——不管從哪扇門——都直接進站。唯一例外是當年沒做完 Step 1 就離開的人，回來仍要補完才能存款或遊戲。
Only a newly created account is pushed into Setup. An existing account goes straight in, whichever door it used. The one exception is someone who abandoned before finishing Step 1 — they still have to complete it before depositing or playing.
同一組 OTP 元件
One OTP component
6 位數、32 秒可重寄、第 3 次重寄後冷卻 03:00、聯絡方式遮罩、有 Invalid 狀態。註冊、登入、忘記密碼、換聯絡方式、提款全部共用這一組。
Six digits, resend at 32s, cooldown to 03:00 after the third resend, masked contact, an invalid state. Sign-up, login, password reset, contact changes and withdrawal all use this same component.
21+ 與條款
21+ and Terms
勾選框是所有註冊方式共用的，社群 icon 也一樣——沒勾就點 icon 會先提示。勾選狀態就是記錄下來的同意（時間戳＋條款版本），Setup 裡不會再問一次。
The checkbox is shared by every sign-up method, social icons included — tapping one while unticked prompts for consent first. The ticked state is the recorded consent (timestamp plus terms version), and Setup never asks again.

畫這張圖時發現的一件事 · One thing this drawing surfaced

Route ② 和 ③ 的終點其實一樣，但入口文案完全相反：註冊頁會直說「這個 email 已經有帳號」，登入頁和忘記密碼卻刻意不透露帳號是否存在。同一個人、同一個 email，從兩扇門進來會得到兩種關於「你有沒有帳號」的答案。這是已知且刻意的取捨，但值得確認業務清楚這件事——因為它讓註冊頁成為唯一可以用來探測 email 是否註冊過的入口。
Routes ② and ③ end in the same place, but their entry copy contradicts each other: sign-up states plainly that the address is registered, while login and password reset deliberately refuse to say. The same person with the same address gets two different answers depending on which door they use. The trade-off is known and deliberate, but worth confirming the business understands it — it makes sign-up the one endpoint that can be used to test whether an address is registered.
